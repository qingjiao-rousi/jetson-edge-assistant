## Validity

- 15/15 measured requests returned HTTP 200 with no structured error.
- All samples used the same model hash, token counts and `finish_reason=length`.
- Deterministic sampling produced one unique output across 15 samples.
- Runtime completed `ready -> requests -> stopped`; no Runtime/collector process remained.
- Clock record shows CPU/GPU min=max and EMC `FreqOverride=1`.

## Locked-clock repeatability check

A second 15-sample run used the same model, prompt, sampling parameters, power mode and locked-clock protocol at `2026-08-12 09:07:49 UTC`. Its operator label was `q4-k-m-clean`, but the repository still had uncommitted changes; the label is therefore **not evidence of a clean build**. This run remains provisional and is used only to check short-run repeatability.

## Claim boundary

This result supports one locked-clock Q4 text baseline under the exact contract above. It does not establish Q8 superiority/inferiority, VLM image latency or accuracy, RAG quality, concurrent throughput, long-run stability, wall power, or a production SLA. A clean committed build should repeat the run before these numbers are promoted into the README or resume.

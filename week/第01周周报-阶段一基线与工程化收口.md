## 四、关键技术结果

固定测试条件：Qwen2.5-3B-Instruct Q4_K_M、Context 4096、batch/ubatch 2048/512、CUDA0、GPU layers 99、Flash Attention 开启、temperature 0、最大输出 128 tokens。测试使用 1 次独立 CLI preconditioning 和 5 次独立 measured process。

| 指标 | Mean | Median | Min | Max |
| --- | ---: | ---: | ---: | ---: |
| Prompt throughput | 329.602 tokens/s | 330.80 | 317.95 | 340.40 |
| Decode throughput | 14.520 tokens/s | 14.52 | 14.50 | 14.53 |
| Prompt eval | 194.346 ms | 193.47 | 188.01 | 201.29 |
| Decode eval | 4821.066 ms | 4820.85 | 4817.56 | 4827.01 |
| Runtime total | 5015.412 ms | 5018.40 | 5005.78 | 5023.43 |
| CLI wall time | 6922.826 ms | 6904.54 | 6895.657 | 6991.543 |

结果说明：

- 5/5 measured run 成功，无失败重试；
- 每次均生成相同的五项电机过热检查建议，输出非空且格式符合固定 Prompt；
- 每次均记录 `offloaded 37/37 layers to GPU`；
- `wall_time_ms` 包含独立 CLI 进程启动和模型加载，不是 TTFT 或 TPOT；
- CLI preconditioning 不是常驻 Runtime 的同进程 warmup；
- 当前结果只能作为 CLI 阶段基线，不能替代后续 DirectBackend 常驻模型指标。

## 六、本周问题与处理

| 问题 | 原因 | 处理结果 |
| --- | --- | --- |
| 首次 CMake 无法找到 nvcc | nvcc 不在 PATH | 显式使用 `/usr/local/cuda/bin/nvcc` |
| `llama-cli` 编译缺少 `mtmd.h` | CMake include 传递范围为 `PRIVATE` | 调整为 `PUBLIC`，修复已提交到个人 fork |
| 编码助手沙箱 CUDA 初始化失败 | Bubblewrap 未透传 `/dev/nvmap` 等设备节点 | 在宿主机验证 CUDA0，避免误判驱动故障 |
| 初始 CUDA 架构未原生包含 Orin | 使用通用 PTX/架构集合 | 固定 `CMAKE_CUDA_ARCHITECTURES=87`，确认生成 `sm_87` |
| NCCL 请求开启但未安装 | 单 GPU Jetson 不需要 NCCL | 固定 `GGML_CUDA_NCCL=OFF` |
| Runtime 快照缺少 Git 元数据 | 最初使用源码压缩包 | 建立个人 fork 和 submodule，固定 commit |
| 主项目最初没有 commit | 仓库处于 unborn 状态 | 创建主项目基线 commit，benchmark 记录 clean commit |

# 二次开发项目现状总结

状态日期：2026-08-06
审查对象：`vlmllm-main` 主项目、`third_party/llama.cpp-omni` 固定子模块、当前
工作树代码、测试、manifest、评测报告和原始 benchmark 目录。

项目背景：本项目基于开源 `llama.cpp-omni` 进行二次开发，Runtime 基础能力
属于开源上游而非本项目自研。完整项目最终实现“工业现场实时音视频全双工多模态交互，以及离线设备
知识检索与故障辅助”。本仓库继续负责既定的 Jetson Runtime、LLM/VLM、量化、
RAG/工具和部署主线；音视频采集、VAD/AEC、ASR、TTS、播放和全双工流控由
其他模块集成，不改变本仓库的开发顺序。

## 1. 结论

本仓库既定后端原型主线已完成 Jetson 基线、文本 Runtime 与服务、Q4/Q8 量化评测、VLM 单图
Runtime 和应用 API、M9.2 手册问答原型、M10.1 单热文本 KV Prefix 复用，以及 M10.2 受限工具与进程内多会话 Agent。M11 已完成半双工语音网关原型的本地资产加载与“键盘文本 -> Agent -> TTS 播放”实测；M12 已完成终端文本 UI。最新 RAG 结论为
M9.1B-R2.5：开发 calibration/diagnostic 通过，但一次最终 holdout 未通过无答案拒绝门，
因此 M9.1B 仍为 `PARTIAL`。

本仓库当前可准确表述为：

> 基于开源 `llama.cpp-omni` 完成 Jetson AGX Orin 端侧 LLM/VLM Runtime 二次开发，
> 已具备文本/单图推理、HTTP/JSON/SSE、模型资产校验、量化与 context 实测，
> 并完成带 citation 的本地手册问答原型和单热文本 session KV Prefix 复用。

当前还不能表述为“完整交付”或“生产可用”。M9.1B 的多文档、向量/混合检索、
真实本地 embedding 和 R2.5 最终质量评测已执行，但无答案拒绝率 `0.50` 低于冻结门
`0.75`，仍为 `PARTIAL`，不得重跑或用该 holdout 调参；Docker/systemd、回滚、并发及
长稳均无完成证据。M11 已完成本地 VAD/ASR/TTS 资产加载和键盘文本播报，但没有完成外接麦克风实测、AEC、打断或实时全双工联调，
不能把完整项目最终功能表述为当前已完成成果。

## 2. 已完成内容

### 2.1 Jetson、源码与构建基线

- 固定上游基线和个人 Runtime fork：
  `third_party/llama.cpp-omni@19cc26967140407efe34006a355ab445b35b16ac`；
- 完成 Jetson AGX Orin 32GB、L4T R36.4.7、CUDA 12.6、GCC 11.4、CMake
  3.22.1 环境审计；
- 完成 ARM64 Release + `GGML_CUDA=ON` 构建，修复 `mtmd` include 传递问题；
- 已建立 environment/build/runtime/model manifest 和模型 SHA-256 追溯；
- 文本基线确认 CUDA0 可用且 37/37 层 offload。

### 2.2 自有文本 Runtime 与服务

- C++ `DirectBackend` 直接链接 `libllama`，完成模型初始化/释放、生成、流式
  callback、context reset、timeout、cancel 和结构化 metrics；
- `RuntimeService` 提供 health、ready、model、metrics 及生成接口，支持
  HTTP JSON 与 SSE；
- `FakeBackend` 覆盖不依赖 GPU 的生命周期和服务契约测试；
- 已有固定 Qwen3 GGUF 的真实模型 integration 记录；
- 当前仍是单模型、单 context、单 active request，不支持真正的多 session 和
  并发队列。

### 2.3 量化、KV 与性能基线

- Qwen3-4B Q4_K_M 与 Q8_0 均完成固定协议测试：S/L/G 三种 workload，每种
  5 次有效 measured，共 15 次/模型，最终目录无失败记录；
- 记录模型加载、Prefill、Decode、tokens/s、UMA、温度和功耗；
- 部署决策冻结为 Q4_K_M 优先、Q8_0 作为高精度对照；
- 当前 DirectBackend 的 KV Cache 固定 F16/F16，未公开受控 Q8/Q4 KV 类型；
- M10.1 已实现一个热文本 session 的 Token ID LCP/Prefix 复用、分叉回滚、最后 Token
  重算、生成 KV 清理和异常失效；Jetson 实机冷热输出一致，热请求 `17/18` 命中并只 Prefill
  1 Token；
- 不支持多 session、LRU、TTL、持久化、跨进程共享、图片/VLM KV 或多用户缓存池；
- AI 辅助盲评在当前有限样本上无法区分 Q4/Q8 质量，不能外推通用质量结论。

### 2.4 VLM Runtime 与应用 API

- 冻结 Qwen2.5-VL-3B-Instruct Q4_K_M 主模型和 Q8_0 mmproj，完成大小、
  SHA-256、GGUF metadata 和 projection binding 校验；
- 实现 `ImageInput`、单图内存输入、JPEG/PNG/WebP 门禁、文件/大小/hash 资产
  校验和 `MtmdBackend`；
- 实现图片 HTTP JSON 传输、SSE `metadata -> token* -> terminal`、图片 token
  和视觉相关指标字段；
- 4096、8192 单图冒烟通过；8192 合成长手册 + 单图严格答案验证通过；
- 16384 完成一次 host-CUDA recovery 实验，32768 未执行且禁用；
- 单个常驻服务完成三张固定图片顺序请求，应用接口
  `POST /v1/diagnose/image` 又完成一次修复后的真实单图 HTTP/SSE 闭环；
- 8192 是当前开发默认 context。上述均为有限冒烟，不代表并发、长稳或平均性能。

### 2.5 RAG M9.1A

- 建立一份带版本、分类和内容 hash 的合成 AX-17 Markdown 手册；
- 按二级标题确定性切分，生成稳定 document/chunk/citation ID；
- 使用冻结 VLM tokenizer 记录真实 token 数；
- 使用 SQLite FTS5 建立离线关键词索引，支持 Top-K、原文片段和来源引用；
- 固定问题集中 5 个有答案问题命中预期 chunk，1 个无答案问题返回空结果且不
  伪造引用；重复构建的文档/chunk manifest 一致；
- 该阶段只有关键词检索，没有 embedding、语义召回、LLM/VLM 答案生成或真实
  设备手册质量评测。

### 2.6 RAG M9.1B（历史 R1 结果）

- 新增 AX-17、BX-9、CT-4 三份合成设备手册，校验 document ID、revision、source 顺序和内容 SHA-256；
- 保持 M9.1A 的 chunk/citation 契约，新增 SQLite float32 L2 embedding、精确 cosine 和 FTS5 hybrid 排序；
- 新增模型指纹、维度、dtype、归一化、索引完整性和向量 blob 门禁；低于配置阈值返回空 results/citations；
- 默认候选为 Qwen3-Embedding-0.6B Q8_0 GGUF；固定 fork 的 `llama-embedding` target 已构建，1024 维、last pooling、L2、Query 指令和文档模板进入 fingerprint；
- 12 题校准集与 12 题最终集相互独立，共 8 个无答案案例；评测器分别覆盖 FTS5、vector、hybrid；
- 已冻结 `Qwen/Qwen3-Embedding-0.6B-GGUF@d20cf9c...`、Apache-2.0、639150592 bytes、SHA-256 和 Xet hash；真实 Provider 冒烟为 1024 维有限 L2 向量；
- 仅用 12 题 calibration-set 冻结 Keyword/Vector/Hybrid 参数，再运行 12 题独立 final set；Hybrid Recall@1/3 `0.50/0.50`、MRR `0.50`、无答案拒绝率 `0.25`、误命中 `3`；
- 冻结质量门要求 Hybrid Recall@1 >= 0.75、Recall@3 >= 0.875、MRR >= 0.80、拒绝率 >= 0.75、误命中 <= 1；五项均失败，因此不得标记 DONE。

### 2.7 RAG M9.1B R2.5（最新：PARTIAL）

- R2.5 以完整英文 token/短语匹配和核心事实族对齐修正 `roller`/`controller` 子串混淆及油品/温度概念混淆；设备 ID、故障码继续只作硬约束；
- calibration 与 diagnostic 均为 R@1 `0.875`、R@3 `0.875`、MRR `0.875`、拒答 `1.0`、误命中 `0`；
- 经一次性 authorization 执行新的 12 题 holdout：R@1/R@3/MRR `0.875/0.875/0.875`，拒答 `0.50`，误命中 `1`；
- 召回和误命中门通过，拒答门失败。holdout 已消费，不得重跑或用于调参；公开结论见 [R2.5 holdout 报告](../evidence/milestones/evaluation/rag-hybrid-m9.1b-r2.5-holdout-public.md)。

### 2.8 M10.2、M11 与 M12

- M10.2 提供 `search_manuals`、`read_manual`、`lookup_fault_code` 三个只读工具、固定最多三步计划、citation 门禁与最多一次重试；JSONL 服务支持 `health`、`answer`、`reset`，最多 8 个进程内 Session、每 Session 20 轮。
- M11 使用本地 sherpa-onnx VAD、流式中文 ASR、VITS TTS 和 PortAudio 构成半双工网关。没有外接麦克风时，真实语音输入不能验收；键盘文本到 Agent 再到 TTS 播放已验证。
- M12 提供终端文本 UI。当前主线 Python 实现位于 `app/`，`scripts/` 只保留薄启动器。

## 5. 主要风险与文档判断

1. M7～M9.1A 已归档到 clean baseline；M9.1B 当前修改尚未提交，真实 embedding
   资产与评测证据已补齐，但质量门失败，需在审查后决定是否归档为 PARTIAL。
2. M9.1B 已支持三份合成 Markdown、多文档身份校验、向量/混合排序和中文/英文质量集；
   真实结果暴露出跨设备关键词干扰和无答案误命中，仍不支持 PDF/日志、重排或模型 grounding。
3. VLM 证据为固定图片的有限顺序冒烟；没有并发、连续长稳、真实设备图片集和
   生产质量阈值。
4. Runtime 仍是单 active request。M10.1 只支持一个热文本 session；不能声称多用户会话、
   LRU/TTL、持久化/跨进程缓存、图片 KV 或并发服务能力。
5. Docker/systemd、鉴权、只读模型挂载、健康恢复、active/previous 回滚和日志
   轮转仅有设计，没有交付文件与运行证据。
6. 历史文档记录的是各里程碑当时状态，其中部分“待实现”已过期；当前状态统一
   以本文件为准，性能事实仍以对应冻结评测报告为准。

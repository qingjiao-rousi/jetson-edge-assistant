# Jetson 工业现场多模态交互与故障辅助系统：项目背景

> 文档定位：本文件是项目业务背景、范围和成果表述的事实入口。
>
> 项目周期设定：三个月。
>
> 真实性原则：本项目基于开源项目进行二次开发，不采用“自研基础 Runtime”或“已有商业产品”的虚构背景。公开案例只用于说明工业现场多模态交互、端侧生成式 AI 和设备故障辅助的现实需求，不代表本项目与相关厂商存在合作。只有代码、日志、模型、测试或部署记录能够证明的内容，才使用“实现”“完成”或“优化”等表述。

## 1. 公开业务依据

本项目选择“工业现场实时音视频全双工多模态交互，以及离线设备知识检索与故障辅助”作为最终业务场景，并非凭空构造。公开市场和开源生态中已经存在以下相近形态：

1. **工业 Copilot 与现场运维助手**：Siemens Industrial Copilot 等公开产品表明，制造业存在使用生成式 AI 辅助工程、运维、故障排查和知识查询的需求。
2. **Jetson 端侧生成式 AI**：NVIDIA Jetson AI Lab 持续提供在 Jetson 上运行本地 LLM、VLM、量化模型和多模态应用的公开示例，证明端侧生成式 AI 是可落地的技术路线。
3. **本地模型服务**：Ollama 等项目已经验证“本地模型管理 + 统一 API + 应用接入”的产品形态，适合作为企业文本助手原型的参考。
4. **离线多模态设备助手**：`autonomous-intelligence` 等开源项目展示了本地对话、视觉、语音、记忆和工具服务的组合方式，可作为应用架构参考，但不代表其全部功能均已生产验证。

参考入口：

- Siemens Industrial Copilot：<https://www.siemens.com/global/en/products/automation/topic-areas/industrial-copilot.html>
- NVIDIA Jetson AI Lab：<https://www.jetson-ai-lab.com/>
- Ollama：<https://github.com/ollama/ollama>
- llama.cpp-omni：<https://github.com/tc-mb/llama.cpp-omni>
- autonomous-intelligence：<https://github.com/OriNachum/autonomous-intelligence>

这些案例只证明同类需求和技术路线存在，不代表本项目与上述厂商存在合作关系。

## 2. 开源二次开发背景

本项目以开源 `llama.cpp-omni` 为核心 Runtime 上游，并参考开源 `llama.cpp`、Jetson AI Lab 和 `autonomous-intelligence` 的公开能力与架构，在固定 fork 上进行 Jetson AGX Orin ARM64/CUDA 二次开发。上游已提供的 GGUF、GGML、CUDA backend、KV Cache、Tokenizer 和 `mtmd` 基础能力不计为本项目从零实现；本项目负责 Adapter、服务接口、资产门禁、可观测性、评测、RAG/工具集成和部署验证。

完整项目最终实现：

> **工业现场实时音视频全双工多模态交互，以及离线设备知识检索与故障辅助。**

工业现场的主要约束包括：

- 维修手册、设备图片和日志包含敏感信息，不能上传公有云；
- 部分现场处于弱网或无网环境，核心推理必须完全离线；
- 需要在 Jetson AGX Orin 32GB 上运行，受统一内存、功耗和散热约束；
- 除文本外，还需要理解设备照片、告警截图和仪表画面；
- 需要引用本地维修手册，输出可追溯的排查步骤；
- 需要观测 TTFT、TPOT、Jetson UMA/RAM、CUDA buffer、温度和功耗，而不只是得到一段回答；
- 需要具备服务重启、日志、健康检查和离线部署能力；
- 音视频交互需要支持采集、VAD/AEC、ASR、视觉输入、LLM/VLM、TTS、播放、打断和全双工流控。

完整系统由两条能力链组成，并共享本地 LLM/VLM Runtime：

~~~text
麦克风 / 摄像头
        ↓
VAD/AEC / ASR / 视频输入编排
        ↓
Jetson 本地 LLM/VLM Runtime
        ↓
TTS / 播放 / 打断与全双工流控

设备照片 / 告警 / 日志 / 本地手册
        ↓
Jetson 本地 LLM/VLM Runtime + RAG + 受限工具
        ↓
带来源的故障分析、排查步骤和结构化报告
~~~

本仓库继续执行原定的 Jetson Runtime、LLM/VLM、量化、RAG/工具和部署主线，并为音视频模块提供请求、流式输出、Cancel 和 Context 接口。修正项目背景不改变既定开发顺序，也不把其他模块负责的实时音视频能力计为本仓库当前已完成成果。

## 3. 目标业务闭环

离线设备知识检索与故障辅助是本仓库的既定业务闭环，不是泛化聊天机器人：

~~~text
故障描述 / 告警截图 / 设备照片 / 本地日志
                    ↓
        Jetson 本地 LLM/VLM Runtime
                    ↓
          本地维修手册 RAG 检索
                    ↓
   故障码查询 / 文件读取 / 日志统计等受限工具
                    ↓
      原因候选、排查步骤、引用来源和维修报告
~~~

业务输出包括：

- 故障现象摘要；
- 可能原因及置信依据；
- 维修手册引用章节；
- 分步排查清单；
- 日志或配置中的关键异常；
- Markdown 或 JSON 结构化报告。

## 4. 三个月实习职责边界

三个月周期内，职责重点是“端侧 Runtime 二次开发与部署验证”，而不是从零实现大模型推理框架。

这里的职责深化不改变项目原有开发主线。工业故障辅助仍按 Jetson 基线、Runtime/服务、量化与 KV Cache、VLM、RAG/工具、部署和交接顺序推进；实习工作只在这些已有任务的关联位置增加工程深度和验证证据。

主要职责：

1. 在 Jetson AGX Orin 32GB 上完成 `llama.cpp-omni` 的 CUDA 构建和问题定位；
2. 接入 GGUF LLM/VLM，验证 tokenizer、chat template、量化类型和模型哈希；
3. 验证 CUDA offload、KV Cache、Prefill/Decode 和流式生成；
4. 设计自有 Backend 接口，隔离应用层与上游 Runtime；
5. 实现请求、响应、超时、取消、错误码和模型生命周期管理；
6. 建立 TTFT、TPOT、吞吐、RAM、GPU、温度和功耗评测链路；
7. 完成文本和图片推理，使用本地 RAG 与受限工具形成业务演示；
8. 完成 systemd 或 ARM64 Docker 的离线部署与异常恢复验证。

不应归为个人原创的上游基础能力：

- GGUF 格式和基础解析；
- GGML 计算图和 CUDA kernel；
- llama.cpp 原有 KV Cache、sampling 和 tokenizer；
- mtmd 的基础视觉/音频编码实现；
- llama.cpp 原有量化算法。

个人贡献应体现在 Jetson 适配、上游问题修复、自有 Runtime/服务接口、指标插桩、量化实验、业务集成和生产化交付。

### 4.1 实习工作在项目中的落点

| 实习工作 | 项目中的既有模块 | 深化内容 | 不能越界的表述 |
| --- | --- | --- | --- |
| 多模型 Jetson 部署与异常定位 | 第1周模型选型、构建和后续 VLM 接入 | 资产 manifest、metadata/template/hash 门禁、加载参数、失败分类和离线一致性验证 | 不把一次冒烟写成多模型稳定部署 |
| C++ 推理模块和模型生命周期 | 第2～4周 `EdgeOmniRuntime`/DirectBackend | 从固定 hash 演进为受控 `ModelSpec`，补充初始化、释放、失败清理和重载测试 | 不声称从零实现 GGUF 格式或 Loader |
| 量化自动化测试 | 第5～6周 Q4/Q8、KV Cache 和性能 | 固定协议、矩阵配置、正确性门禁、原始日志、统计与 provenance | 未获得并加载 F16 时不声称完成 F16 对比 |
| 长上下文与 OOM 分析 | 第6周及第8周 context 实测 | 区分权重、KV、compute buffer 和应用 RAM，记录 context/batch 与初始化失败边界 | Jetson 为 UMA，不把 RAM 等同于独立显存 |
| CMake/CUDA 与服务可靠性 | 第1～4周构建/服务及第11～12周部署/回归 | 一键构建、版本追溯、流式输出、Timeout/Cancel、结构化日志和异常后恢复 | 不把协作式取消写成 CUDA 即时抢占 |

每条实习经历必须能回指项目中的代码、测试、原始日志和结论文档。它们增强的是原项目的工程可信度，不构成新的产品架构或另一条开发路线。

## 5. 功能优先级

### 5.1 P0：三个月业务主线

- Jetson CUDA/ARM64 构建；
- GGUF 模型校验与版本记录；
- LLM 文本推理；
- Q4_K_M/Q8_0 权重量化对比；
- KV Cache 配置与占用观测；
- Prefill/Decode、TTFT、TPOT 和 tokens/s；
- 自有 C++ Runtime Adapter；
- 流式生成、超时、取消和错误处理；
- Jetson RAM、GPU、温度和功耗采集；
- systemd 或 ARM64 Docker 离线部署。

### 5.2 P1：业务亮点

- VLM 图片/截图输入；
- 图片 token 与视觉编码耗时；
- 本地 PDF、Markdown、文本和日志 RAG；
- 2～3 个只读或受限工具；
- 带引用来源的故障排查报告。

### 5.3 P2：时间允许时扩展

- 离线音频文件输入；
- 简单语音交互；
- 多 session；
- Docker 与 systemd 同时交付；
- 更长上下文和更多 KV Cache 精度实验。

### 5.4 不作为本仓库三个月主线承诺

- 实时全双工音视频的采集、ASR/TTS、播放和流控实现（仍属于完整项目最终功能）；
- 通用自主 Agent；
- 大规模并发服务；
- 从零实现 llama.cpp/GGML；
- 同时完成蒸馏和剪枝并达到生产质量；
- 未经实测的性能、精度或功耗结论。

## 6. 个人模型压缩研究方向

蒸馏和剪枝不纳入本仓库三个月主交付，归为业务之外的个人学习与后续实验。

只选择一个方向进入实验：

### 方向 A：知识蒸馏

- 固定 Teacher、Student 和数据集；
- 设计 logits 或 feature distillation loss；
- 保存训练配置和 checkpoint；
- 比较任务质量、模型大小和推理性能；
- 导出或转换为目标 Runtime 可加载格式；
- 在 Jetson 上重新验证。

### 方向 B：结构化剪枝

- 选择 Attention Head、FFN、层数或 Vision Projector 中的一类；
- 记录剪枝比例和判据；
- 完成恢复训练；
- 比较精度、参数量和端侧性能；
- 重新量化并在 Jetson 部署。

研究方向只有在具备数据、训练代码、checkpoint、对照指标和 Jetson 部署结果后，才能表述为“完成实验”。否则只能表述为“调研”或“计划”。

## 8. 推荐成果表述

项目完成后，可根据实际证据选择以下表述；完整项目目标与本仓库已完成成果必须分开：

> 项目基于开源组件进行二次开发，最终面向工业现场实现实时音视频全双工多模态交互，以及离线设备知识检索与故障辅助。

> 基于 llama.cpp-omni 二次开发 Jetson 端侧离线 LLM/VLM 推理系统，完成 GGUF 模型接入、CUDA offload、自有 Runtime Adapter、流式生成和异常处理。

## 9. 当前实现同步（2026-08-06）

本节更新当前事实，不改变前述业务背景、职责边界或完整项目目标。

- M9.2 已完成本地维修手册检索、来源引用和本地模型生成回答的原型闭环；M9.1B-R2.5 的最终质量门仍为 `PARTIAL`，已消费 holdout 不得重跑或调参。
- M10.1 已验证单热文本 session 的 KV Prefix 复用；它不是多用户缓存，也没有 LRU、TTL、持久化、跨进程共享或 VLM KV 复用。
- M10.2 已完成只含 `search_manuals`、`read_manual`、`lookup_fault_code` 的受限 Agent 与进程内有界 session；它不是 Runtime 多 session KV，也不含生产鉴权或持久化。
- M11 已实现 PortAudio、sherpa-onnx VAD/ASR/TTS 的半双工语音网关原型。本地资产加载以及“键盘文本 -> Agent -> TTS 播放”已验证；未接入外部麦克风，未完成真实语音输入、AEC、打断或全双工。
- M12 已提供终端文本 UI。Docker/systemd、长稳、回滚、生产并发和完整实时音视频系统仍未交付。

当前代码职责、配置位置和验证入口以 [当前开发指引](../docs/current/development-guide.md) 为准；冻结实验和历史周报位于 `../evidence/`。

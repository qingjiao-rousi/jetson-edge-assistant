# M9.1B Offline Multi-Document Hybrid Retrieval

M9.1B extends the frozen M9.1A `Document`/`Chunk`/`Citation` contract to three synthetic Markdown equipment manuals. Sources are repository-relative, sorted lexicographically, and must match `document_id`, `revision`, and byte-level SHA-256 values in `configs/rag-hybrid-m9.1b.json`. Duplicate document IDs, duplicate chunk IDs, path traversal, absolute paths, changed hashes, and unstable source ordering are rejected.

The index is SQLite-only and has schema version 2. It keeps the M9.1A FTS5 table and adds an embedding metadata table plus float32 L2-normalized vectors. Query results expose `vector_score`, `keyword_score`, `final_score`, document/chunk IDs, original text, and the stable citation. Ties use source order, section ordinal, and chunk ID. Vector/keyword weights and the no-hit threshold are intentionally `null` until the separate calibration set runs with the real model; the earlier provisional `0.7/0.3/0.55` values are not reused. A candidate below the calibrated threshold returns `answerable=false`, empty `results`, and empty `citations`.

The default deployment candidate is `llama-cpp-gguf` with `Qwen3-Embedding-0.6B Q8_0`: dimension `1024`, last-token pooling, float32 output and L2 normalization. The fixed fork builds `llama-embedding` without source changes and exposes `--pooling last`, `--embd-normalize 2`, and JSON-array output. The query template is `Instruct: Retrieve the industrial equipment manual passage that best answers the maintenance or fault-diagnosis query.\nQuery: {text}`; documents use `{text}` without an instruction. Both templates and all runtime/model fields enter the embedding fingerprint. `sentence-transformers-local` remains an optional compatibility provider.

The GGUF provider refuses to start until model ID, repository, immutable revision, license, Q8_0 path, byte size, SHA-256 and Xet hash are all frozen. It validates the executable and model under repository-controlled roots, verifies size and hash before execution, batches through `llama-embedding`, and validates count, dimension, finite values and L2 normalization. Existing Qwen3 Instruct and VLM weights are never admitted as retrieval embeddings.

The 12-question threshold calibration set and disjoint 12-question final evaluation set cover multi-document routing, synonym rewriting, exact fault codes, similar-device distractors, English/Chinese boundaries, and explicit no-answer cases. Eight of 24 questions are no-answer cases. Calibration and evaluation are separate commands: the final command consumes only a frozen calibration artifact and rejects overlapping IDs, a changed embedding fingerprint or a changed quality gate. The frozen Hybrid gate requires Recall@1 >= 0.75, Recall@3 >= 0.875, MRR >= 0.80, no-answer rejection >= 0.75 and at most one false positive.

The real 2026-08-04 evaluation remains `PARTIAL`: the asset and execution gates passed, but Hybrid achieved only Recall@1/3 `0.50/0.50`, MRR `0.50`, no-answer rejection `0.25` and three false positives. These facts are not used to retune the frozen parameters.

M9.1B does not generate answers, inject retrieved context into VLM, or claim general retrieval quality. Those activities belong to M9.2 or a later audited corpus.

The exact external gate and authorized acquisition choices are listed in [qwen3-embedding-asset-requirements-m9.1b.md](qwen3-embedding-asset-requirements-m9.1b.md).
